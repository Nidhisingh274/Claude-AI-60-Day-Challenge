01

NumPy Basics

arraysndarrayindexingslicingdtypes

A Python list can hold anything, in any mix, anywhere in memory. A NumPy ndarray gives up that flexibility on purpose: every element is the same fixed-size type, packed contiguously in memory. That trade is exactly what makes array math in AI fast.

Analogy A Python list is a row of labeled lockers, each one a different size, holding anything from a shoe to a sandwich, scattered across a building. A NumPy array is a train of identical train cars bolted together in a straight line — because every car is the same shape, the whole train can accelerate, brake, and turn as one unit. That uniformity is what "vectorized" math exploits later in this tutorial.

Creating arrays

The most common entry point is np.array(), which converts a Python list (or list of lists) into an ndarray:

import numpy as np

a = np.array([1, 2, 3, 4])
print(a, a.shape, a.dtype)
→ [1 2 3 4] (4,) int64

For AI work you'll rarely type out arrays by hand — you'll generate them. These constructors show up constantly when initializing weights, masks, or placeholder tensors:

np.zeros((3, 4))       # 3x4 array of 0.0 — common for initializing bias terms
np.ones((2, 2))        # 2x2 array of 1.0
np.arange(0, 10, 2)   # [0 2 4 6 8] — like range(), but returns an array
np.linspace(0, 1, 5)   # [0. 0.25 0.5 0.75 1.] — 5 evenly spaced points
np.random.randn(3, 3) # random weight matrix, standard normal distribution

Shape, dtype, and why they matter

Every array carries three things you should check by reflex: .shape (the dimensions), .dtype (the element type), and .ndim (how many axes). In AI code, a mismatched shape is the single most common bug — a model expecting (batch, 784) will fail silently or loudly on (784, batch).

PropertyMeaningExample
.shapeSize along each axis(3, 4) = 3 rows, 4 columns
.dtypeElement data typefloat32, int64, bool
.ndimNumber of axes1 = vector, 2 = matrix, 3+ = tensor
.sizeTotal element count3×4 array → 12
Common Misconception "Shape (3,) and shape (3,1) are basically the same thing." They are not. (3,) is a flat 1-D vector; (3,1) is a 2-D column matrix. This exact confusion causes some of the most stubborn bugs when feeding data into ML models — always print .shape when something looks wrong.

Indexing and slicing

Indexing pulls out single elements; slicing pulls out a view of a range. NumPy extends Python's list[start:stop:step] syntax across every axis at once, separated by commas.

m = np.array([[10,20,30], [40,50,60], [70,80,90]])

m[1, 2]      # 60 — row 1, column 2
m[0]         # [10 20 30] — entire row 0
m[:, 1]      # [20 50 80] — entire column 1
m[0:2, 1:]    # [[20 30],[50 60]] — sub-matrix
Common Misconception "Slicing an array copies it, just like slicing a list." A NumPy slice is a view, not a copy — it shares memory with the original array. Modifying a slice modifies the source data. If you need an independent copy, call .copy() explicitly.

Key Takeaways

  • ndarrays store one fixed dtype in contiguous memory — that's the source of NumPy's speed
  • .shape, .dtype, and .ndim should be checked whenever a bug appears
  • Comma-separated indices index across axes: arr[row, col]
  • Slices are views into the original memory, not independent copies
💻 Practical Exercise — Predict the output

Given g = np.arange(12).reshape(3,4) (a 3×4 grid of 0–11), what does g[1:, ::2] return? Think about it, then reveal.

Reveal answer
Rows 1–2, columns 0 and 2 → [[4, 6], [8, 10]]. 1: skips row 0; ::2 takes every other column starting at 0.

Array Operations & Broadcasting

🔒

vectorizationbroadcastingelement-wise ops

This module explains the single habit that separates fast AI code from slow AI code: replacing explicit for loops with vectorized array operations.

Vectorization: the loop you don't write

Compare two ways of doubling every value in a dataset of one million numbers:

# Pure Python — interprets every element, one at a time
result = [x * 2 for x in data]

# NumPy — pushes the loop down into pre-compiled C code
result = data * 2

Both produce the same values. On a million-element array, the vectorized version is typically 10–50x faster, because NumPy performs the loop in compiled C rather than the Python interpreter, and it can use CPU-level parallel instructions (SIMD) across contiguous memory.

Analogy A Python for loop is one clerk stamping a thousand documents by hand, one at a time. A vectorized NumPy operation is a printing press: load all thousand sheets at once, pull the lever once, and every sheet is stamped simultaneously. The press only works because all the sheets are the same size — which is exactly the uniform-array constraint from Module 1 paying off.

Broadcasting: math between different shapes

Broadcasting lets NumPy apply an operation between arrays of different shapes by "stretching" the smaller one, without actually copying data. Two shapes are broadcast-compatible when, comparing dimensions from the right, each pair is either equal or one of them is 1.

prices = np.array([100, 200, 300])   # shape (3,)
tax_rate = 1.08                        # shape () — a scalar
prices * tax_rate  # [108. 216. 324.] — scalar "stretches" across all 3

batch = np.ones((4, 3))              # shape (4, 3) — 4 samples, 3 features
mean  = np.array([10, 20, 30])      # shape (3,)
batch - mean    # mean row is applied to all 4 rows — used constantly for normalization

This exact pattern — subtracting a per-feature mean from a batch of samples — is how every neural network standardizes input data before training.

Shape AShape BCompatible?Result shape
(4, 3)(3,)✅ Yes(4, 3)
(4, 3)(4, 1)✅ Yes(4, 3)
(4, 3)(4,)❌ NoValueError — 3 vs 4 mismatch
Common Misconception "Broadcasting duplicates the smaller array in memory to match the bigger one." It doesn't — NumPy simulates the stretch mathematically without allocating the extra memory, which is part of why broadcasting is both fast and memory-efficient, not just a syntax shortcut.

Element-wise vs. matrix operations

* multiplies element-by-element. Matrix multiplication is a different operation entirely, done with @ or np.dot() — this distinction becomes critical in Module 4.

Key Takeaways

  • Vectorized operations replace Python loops with compiled, parallelized C code
  • Broadcasting compares shapes from the right; dimensions must match or be 1
  • No extra memory is allocated during broadcasting — it's a virtual stretch
  • * is element-wise; matrix multiplication needs @ or np.dot()
💻 Practical Exercise — Fix the shape error

batch has shape (5, 3) (5 samples, 3 features) and you want to subtract a per-feature mean array of shape (3,). Will batch - mean work, and why?

Reveal answer
Yes. Comparing from the right: 3 vs 3 → match, 5 vs (missing) → treated as 1, so mean is broadcast across all 5 rows. Result shape: (5, 3).

Reshaping, Stacking & Aggregation

🔒
Complete Module 2's quiz to unlock this module.
reshapetransposestack/concatenateaxis reductions

Raw data rarely arrives in the shape a model needs. This module covers reshaping arrays into new dimensions and collapsing them down with aggregations — the two operations that bridge "data you have" and "data your model accepts."

Reshaping without copying data

.reshape() reorganizes the same underlying data into a new shape, as long as the total element count matches:

flat = np.arange(12)              # shape (12,)
grid = flat.reshape(3, 4)         # shape (3, 4) — same 12 numbers, new layout
img  = flat.reshape(2, 2, 3)      # shape (2, 2, 3) — e.g. a tiny 2x2 RGB image
auto = flat.reshape(4, -1)       # -1 means "figure this dimension out" → (4, 3)
Analogy Reshaping is like rearranging the same 12 dinner rolls from one long row into a 3×4 tray. You haven't baked new rolls or changed any of them — you've only changed how they're grouped for serving. The dough (memory) stays identical; only the tray (shape) changes.

Transpose and stacking

.T flips rows and columns — essential when a matrix is oriented backwards from what a formula expects. np.stack, np.vstack, and np.hstack combine multiple arrays into one, which is exactly how individual samples get assembled into a training batch.

a = np.array([1,2,3])
b = np.array([4,5,6])

np.vstack([a, b])   # [[1 2 3],[4 5 6]] — stack as new rows
np.hstack([a, b])   # [1 2 3 4 5 6] — stack side by side
np.stack([a, b])    # same as vstack here — stacks along a new axis

Aggregations and the axis argument

Functions like .sum(), .mean(), .max(), and .argmax() collapse an array down. The axis argument controls which dimension gets collapsed — this trips up almost everyone at first.

m = np.array([[1,2,3], [4,5,6]])   # shape (2, 3)

m.sum()          # 21 — collapse everything to one number
m.sum(axis=0)  # [5 7 9]  — collapse DOWN the rows → one value per column
m.sum(axis=1)  # [6 15]   — collapse ACROSS the columns → one value per row
Common Misconception "axis=0 means 'operate on rows' and axis=1 means 'operate on columns'." Backwards, intuitively. axis=0 means "walk down that axis and collapse it" — which merges values across rows, producing one result per column. Reading it as "the axis that disappears" is more reliable than "the axis you operate on."
CallWhat collapsesOutput shape from (2,3)
m.sum()everythingscalar
m.sum(axis=0)the row axis(3,) — per column
m.sum(axis=1)the column axis(2,) — per row

Key Takeaways

  • .reshape() reorganizes data without copying, as long as element counts match
  • .T transposes; vstack/hstack/stack combine arrays into batches
  • axis names the dimension that gets collapsed, not the dimension you "keep"
  • Always sanity-check aggregation results against the expected output shape
💻 Practical Exercise — Batch mean

You have scores with shape (100, 5) — 100 students, 5 test scores each. Which axis do you average over to get one overall average per student?

Reveal answer
scores.mean(axis=1) → shape (100,). Collapsing axis 1 (the 5 test scores) leaves one average per student.

AI/ML Applications

🔒
Complete Module 3's quiz to unlock this module.
dot productmatrix multiplicationnormalizationneural net layer

Everything so far converges here: a single dense (fully-connected) neural network layer is nothing more than a matrix multiplication, a broadcasted addition, and an element-wise activation function — all NumPy operations you already know.

Dot products: the atomic operation of AI

The dot product multiplies two vectors element-wise and sums the result. It's how a neuron combines its inputs and weights into a single number:

inputs  = np.array([1.0, 0.5, 2.0])   # 3 input features
weights = np.array([0.2, 0.8, -0.1])  # 3 learned weights

np.dot(inputs, weights)  # 1.0*0.2 + 0.5*0.8 + 2.0*-0.1 = 0.4
Analogy A dot product is a grocery receipt: multiply each item's price by its quantity, then sum every line to get one total. A neuron does the same arithmetic — multiply each input by its weight (its "price"), then sum for one output value.

Matrix multiplication: dot products at scale

A dense layer applies the same weighted-sum operation to an entire batch of samples and every output neuron at once, using @ (matrix multiplication). For A @ B to work, A's number of columns must equal B's number of rows.

X = np.random.randn(32, 784)   # batch of 32 images, each flattened to 784 pixels
W = np.random.randn(784, 128)  # weights connecting 784 inputs to 128 neurons
b = np.zeros(128)               # one bias per neuron

Z = X @ W + b   # shape (32, 128) — broadcasting adds b to every row

That single line — X @ W + b — is the forward pass of a dense layer in every framework, whether it's raw NumPy, PyTorch, or TensorFlow underneath the abstractions.

Activation functions: element-wise, not matrix ops

After the matrix multiply, an activation function is applied element-wise — no shape change, just a per-element transformation:

def relu(x):
    return np.maximum(0, x)   # element-wise: negative values become 0

A = relu(Z)   # shape stays (32, 128)

Normalization: broadcasting in practice

Before training, features are typically standardized to mean 0, standard deviation 1 — directly reusing Module 2's broadcasting and Module 3's axis reductions:

mean = X.mean(axis=0)   # shape (784,) — per-feature mean across the batch
std  = X.std(axis=0)    # shape (784,) — per-feature std across the batch
X_norm = (X - mean) / std  # broadcasting (32,784) against (784,)
OperationOperatorShape rule
Element-wise multiply*Shapes must match or broadcast
Matrix multiply@ / np.dotInner dimensions must match: (n,k)@(k,m)→(n,m)
Activation (ReLU, sigmoid...)function callShape unchanged
Common Misconception "* and @ are interchangeable for arrays that happen to be square." They compute entirely different things even when shapes allow both to run without error. * is element-wise; @ sums products across a shared dimension. Silently using the wrong one is a classic, hard-to-spot AI bug because the code runs — it just learns nothing correctly.

Key Takeaways

  • A dot product is a weighted sum — the core computation of a single neuron
  • X @ W + b is the forward pass of a dense layer, for a full batch at once
  • Activation functions apply element-wise and never change shape
  • Normalization combines axis-aware aggregation with broadcasting
💻 Practical Exercise — Shape-check a layer

Input batch X has shape (16, 20). You want an output of shape (16, 8). What shape must the weight matrix W be for X @ W to work?

Reveal answer
W must be shape (20, 8). Inner dimensions 20 and 20 cancel, leaving outer dimensions (16, 8).

Final Practical Challenge

🔒
Complete all 4 modules to unlock the final challenge.

Using only what you've learned, implement the forward pass of a 2-layer neural network (a "multilayer perceptron") by hand with NumPy.

The brief

Given a batch of inputs X of shape (batch, in_features), weights/biases W1, b1, W2, b2, compute:

  1. Z1 = X @ W1 + b1, then apply ReLU → A1
  2. Z2 = A1 @ W2 + b2 → the final output, no activation (raw scores)
💻 Attempt it, then reveal the reference solution 
import numpy as np

def relu(x):
    return np.maximum(0, x)

def forward(X, W1, b1, W2, b2):
    Z1 = X @ W1 + b1      # hidden layer pre-activation
    A1 = relu(Z1)          # hidden layer activation
    Z2 = A1 @ W2 + b2     # output layer (raw scores / logits)
    return Z2

X  = np.random.randn(8, 20)      # batch of 8, 20 features
W1 = np.random.randn(20, 16) * 0.1
b1 = np.zeros(16)
W2 = np.random.randn(16, 3)  * 0.1
b2 = np.zeros(3)

out = forward(X, W1, b1, W2, b2)
print(out.shape)   # (8, 3) — 8 samples, 3 output classes

Summary Notes

  • NumPy arrays trade Python's flexibility for uniform, contiguous memory — that's the entire speed story
  • Vectorize first, loop never (in AI code): reach for array ops before for loops
  • Broadcasting rules compare shapes from the right; match or 1, every time
  • axis names the dimension that disappears from the result
  • * is element-wise, @ is matrix multiplication — never confuse them
  • A neural network layer is X @ W + b followed by an element-wise activation — nothing more mystical than that
