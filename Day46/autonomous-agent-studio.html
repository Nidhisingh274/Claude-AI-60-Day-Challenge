Architecture overview

How the stop-check governs information flow

Each round is a real, sequential API round-trip chain: Evaluator scores the current draft against a fixed rubric, Critic receives that score plus its reasoning and finds concrete gaps, and Improver receives the draft, evaluation, and critique together to produce the next draft. After Improver returns, Memory Manager distills what changed into a running memory note that is threaded into the next round's Improver call, and Safety Monitor screens the new draft for unsafe or overconfident clinical claims before the loop is allowed to continue. The stop-check runs after every round in strict order — plateau, then threshold, then hard cap — and its result determines whether another Evaluator call fires or the loop exits to Final Reviewer.

Extension ideas

Where this pipeline could go next

Guideline retrieval grounding

Give Executor a web-search or MCP tool call against UpToDate-style or PubMed sources so differentials are grounded in retrieved evidence rather than parametric knowledge alone, with citations carried through to Final Reviewer.

Multi-case memory bank

Persist Memory Manager notes across sessions (e.g. via the Artifacts storage API) so recurring diagnostic blind spots the Critic keeps flagging get surfaced automatically on future cases.

Human-in-the-loop gate

Insert an approval step before Final Reviewer where a clinician can accept, reject, or annotate the draft — turning the autonomous loop into a supervised one for higher-stakes deployments.

Parallel specialist critics

Run Critic as three parallel calls (infectious disease lens, cardiovascular lens, red-flag/can't-miss lens) and merge their outputs before a single Improver pass, trading latency for broader coverage per round.
