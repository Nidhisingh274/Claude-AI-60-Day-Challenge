# 🧠 Content Intelligence Studio

**A premium AI-powered content analysis platform built with Claude for the #60DayClaudeChallenge**

> *Turn any piece of content into a full recruiter-ready audit. Scores, rewrites, platform recommendations, and a downloadable report in under 2 minutes.*

Content Intelligence Studio runs a **6-stage pipeline of specialized AI reviewers** over any text, code, or image content you give it, then returns a SaaS-grade dashboard: overall scores, category breakdowns, AI reasoning, strengths, weaknesses, missed opportunities, platform-specific recommendations, rewritten versions, a publishing checklist, and a comprehensive downloadable report.

Built to review content aimed at **GitHub, LinkedIn, and portfolio sites** with the explicit goal of helping engineers build credibility and stand out for AI/GenAI engineering roles.

## 🏗️ Architecture

```
User Input (text / code / image / any combination)
        │
        ▼
  Content-Type Detector  ──►  detects: Text / Code / Image / Combo
        │
        ▼
  Smart Model Router  ──►  routes each stage to the right model
        │
        ├── Lightweight stages      → openai/gpt-oss-20b   (fast, low-cost)
        ├── Deep-reasoning stages   → openai/gpt-oss-120b  (highest quality)
        └── Any image present       → qwen/qwen3.6-27b     (multimodal/vision)
        │
        ▼
┌───────────────────────────────────────────────────────────┐
│         6-Stage Reviewer Pipeline (all live API calls)     │
├───────────────────────────────────────────────────────────┤
│  1. Content Strategist   — clarity, engagement, structure   │
│  2. Technical Reviewer   — AI/ML depth, code quality        │
│  3. Hiring Manager       — hireability signals, red flags   │
│  4. Platform Optimizer   — GitHub / LinkedIn / Portfolio    │
│  5. Visual Analyst       — screenshots, thumbnails (vision) │
│  6. Report Synthesizer   — merges all 5 into final report   │
└───────────────────────────────────────────────────────────┘
        │
        ▼
  Premium SaaS Dashboard  ──►  scores · rewrites · checklist
                               before/after · downloadable report
```

### Key Engineering Decisions

- **No hardcoded scoring, zero canned feedback** : every number, insight, and rewrite is a live API response
- **Deliberate model load-splitting** : high-stakes stages (Technical + Hiring Manager) run on the strongest model; simpler stages use the faster, lighter model to stay within free-tier rate limits (8,000 TPM)
- **Self-healing 429 handling** : parses Groq's own `retry-after` signal and retries automatically rather than failing outright
- **Graceful multimodal degradation** : if the vision model fails, the pipeline falls back to a text-only pass rather than crashing

## 💡 Key Learnings

**Multi-agent pipelines beat single-prompt analysis.** Giving each reviewer a narrow, expert-framed role (strategist vs. technical reviewer vs. hiring manager) produced noticeably sharper, more actionable feedback than one big prompt trying to do everything. The specialization is visible in the output.

**Model routing is a real production concern, not a nice-to-have.** Free-tier rate limits forced deliberate architectural decisions — which stages need the most powerful model, which can run on something lighter. This is exactly the tradeoff real production AI systems make.

**Multimodal review changes what's possible.** Handing the AI a raw screenshot and getting direct visual feedback and not just OCR'd text, is qualitatively different from text-only review. Visual content analysis surfaced issues that text analysis would have missed entirely.

**Honest AI framing builds trust.** Every predicted-performance number in the report is explicitly labeled as an AI estimate, not a guarantee. This is a small detail that matters a lot when building AI products people will actually trust.

**The "interview before you build" pattern works.** The whole app was spec'd through a structured MCQ interview with Claude before a single line of code was written. The resulting design was more focused and better-constrained than anything that would have come from just starting to code.

## 📝 The Original Prompt

This is the exact brief that kicked off the build, via an interview-style, one-question-at-a-time process before any code was written:

> **Content Intelligence Studio**
> You are an expert content strategist, platform growth specialist, creator coach, behavioral psychologist, prompt engineer, AI systems architect, UX designer, and senior frontend developer. Interview first, one question at a time, using MCQs only...
>
> After the interview, build a polished single-page HTML application called Content Intelligence Studio that acts as an AI content consultant. The app should accept both text and image inputs and analyze them using a live LLM API — no key required from the code's perspective (key entered by the user at runtime).
>
> Every insight, score, explanation, and recommendation must come directly from the AI through live API calls. Do not use hardcoded logic, placeholder analysis, canned feedback, or rule-based scoring.
>
> Build constraints: Single self-contained HTML file using only vanilla HTML, CSS, and JavaScript. No external libraries. Commercial-grade UI/UX, responsive design, dark mode, smooth animations, interactive visualizations, robust error handling, loading states, graceful retry logic, and zero syntax errors.

**Interview answers that shaped the reviewer pipeline:**

| Question | Answer |
|---|---|
| Content type | Research / education / business / code (technical portfolio content) |
| Platform | GitHub, LinkedIn, Portfolio |
| Primary goal | Build credibility, attract AI/GenAI engineering opportunities, showcase projects |
| Upload types | Text, code, images, or any combination |
| Review criticality | Professional, honest, senior-manager lens — balanced across all reviewers |
